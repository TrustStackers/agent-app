Issue a Credential

Community-issued credentials (VMC/VRC) require a VTC as issuer and admin co-signatures. Peer verification (DTG RelationshipCredential) uses personhood proof — no VTC needed. Choose your method below.

🫂 Verify a Peer (DTG RelationshipCredential)

This verifies a real person behind a relationship. Select a bidirectional connection, then press I know this person. Both of you must confirm within 60 seconds — then the DTG RelationshipCredential is created. No community required.

📜 Issue a Community Credential (VMC/VRC/VEC)

Uses a VTC (Verified Trust Community) as the issuer. The credential is signed with this agent's own key, so no other admin's key is needed on this form.

A subject is named by a CESR VID (a public key beginning z…), not a DID. Relationships list peers by DID, so a peer's VID has to be pasted here — sending a DID is refused with invalid_input rather than silently minting a credential nobody can read back.

Only VTCs you are an admin of can issue credentials. If you don't see any, create a VTC first or use the peer verification flow above.

Must be one of the community's allowed claim types — a type it does not allow is refused with claim_not_allowed, and the error names the ones that would work.

Verify a Credential

Verifies a credential against its issuer's governance document: the digest must match its canonical fields, and at least the community's threshold of signatures must come from its current admin list.

Credentials issued by a VTC are listed here. Each is addressed by its issuer, subject and claim type — the store's own key for it — because a store credential has no row id and the older :id/verify route addressed one that was never returned.
